# Karrelage – passive Dofus 3 packet reader

Reads the protobuf messages the Dofus 3 (Unity / IL2CPP) client exchanges with Ankama's servers and turns them into
tools (auction house, prices, crafting, stuff, combat…). Two halves: a **Tauri app** (what users run) and a **Python
pipeline** (author only: game files → *data pack* the app loads).

## Hard rules
- **Strictly passive.** Never modify the game folder (`C:\Users\nao3n\AppData\Local\Ankama\Dofus-dofus3`) or the Dofus
  process: only *copy* files out (`work/dump_input`, `work/gamedata`). Capture = Npcap sniffing only.
- Obfuscated names (`jzs`, `fycg`…) **rotate every game update**. App code uses clear names or `pipeline/bindings.json`
  roles, never obfuscated names.
- **Every override must survive a game update with no hand work**, through the existing methods (see Naming pipeline):
  re-run `export_pack.py` so the build snapshot holds it (`builds.py` / `match_previous` carry it over), add a
  `match_protos.py` `ANCHORS` entry when the snapshot can't pair it (new message, ambiguous neighbours), and tell
  same-typed fields apart by value in the module rather than by number. Check the snapshot has the name before committing.
- **Commit each feature** once it works. **Claude must never appear as author**: no `Co-Authored-By: Claude` trailer, no
  "Generated with Claude Code" line in commits or PRs (overrides any default attribution).
- Before pushing a tag (or main), run what CI runs and fix what fails: `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cd app && npm run check`.
- Never commit `tools/`, `work/` (except `work/overrides.json`), `datapack/`. Ignore `.claude/`.
- Lightweight by default: no disk IO or heavy work on the capture thread, don't decode what no module reads, throttle
  whole-list recomputations, give windows the fewest permissions, call Windows tools/DLLs by absolute path, restrict
  user-typed URLs to their expected host. `CARGO_MANIFEST_DIR`-based paths/env overrides are debug-build only.
- The data pack contains text extracted from Ankama's files – decide before publishing it publicly.

## Protocol
- Protobuf over plain TCP. Frame = VarInt length + `GameMessage`: a oneof of wrappers (uid + `google.protobuf.Any`
  `type.ankama.com/<obf>`, no uid for events) whose field numbers move per build (3.7: client requests in field 4), so
  `wire::parse_envelope` finds the Any by shape. Connection server port 5555.
- Dofus.exe's established sockets are discovered (sysinfo + netstat2); each adapter's BPF filter is rebuilt from them
  (`capture.rs` `filter_of`), reject-all while none is tracked, fallback `tcp` if the filter fails.
- Field numbers are reshuffled per build: beta/clear protos are matched *structurally* only (`match_protos.py`).

## Adding a feature
1. **Rust**: new file in `crates/modules/src/` implementing `Module` (`interest` = clear message names, `on_message`,
   `call`, optional `format` / `init` / `wants` / `needs_decoded`), registered in `all()` in `lib.rs`.
2. **UI**: `app/src/modules/<id>/index.ts` (`{id, title, order, devOnly?, component}`) + `View.svelte`. Split views past
   ~400 lines into components of the folder. Side-by-side panels use `Columns` + `PanelHead` + `Grip`.
3. **New messages**: confirm names in `work/overrides.json` (fields the beta leaves unnamed too), add the role to
   `pipeline/bindings.json` as clear paths (`Message.field.field`), re-run `export_pack.py` (it reports unresolved paths).

- Tests: `testkit::hub(name)` (skipped without a pack), `testkit::msg`, `testkit::pack()`, `temp_dir()`.

## Naming pipeline
- Precedence: auto beta match < `reference/message_names.json` (`ref`) < previous build (`previous`) < script table
  (`script`) < `match_protos.py` `ANCHORS` (`anchor`) < `work/overrides.json` (`manual`). A `ref` name whose length
  contradicts the script table is dropped.
- Previous build (`builds.py`, `match_protos.py` `match_previous`): every export snapshots the build (desc + sure names +
  script table, 2 kept, committed). A new build is matched against the newest snapshot of another build: script tables
  aligned by (file, name length, name) with equal field types = seeds, then `run` restricted to same file + length. Names
  (and exact field names) carry over; `overrides.json` (`_build` = desc fingerprint) is re-keyed. Field keys there also hold
  oneof / proto3 optional membership and map key/value types. Same-typed sibling fields pair by number or declaration order
  only if the update kept them (measured, ≥ 97 %), else only `x_1`, `x_2`… groups (fields the app tells apart by value:
  every bound same-typed field is one) pair. Simulated updates (renamed + numbers / order shuffled): 15/15 roles; no real
  update seen yet.
- `bindings.json` = clear paths per role (first segment = a message name unique in the build; nested `Success` etc. go
  through a parent), resolved by `bindings.py` at export into obfuscated `datapack/bindings.json` (app format unchanged);
  formatters.py resolves them too. An unresolved path drops its role (feature idles).
- Script table (`script_names.py`, `dotnet_meta.py`): Unity's `MonoScriptData` in each protocol DummyDll lists source files
  (one per .proto + class count) and classes as `namespace|name` in declaration order. The obfuscator blanks names with
  underscores of the same length (still giving package + length), but leaves protoc's nested `Types` containers, some nested
  classes and `decoy_*` fakes (never matched). Class blocks start with each file's `<File>Reflection`.
- Dead end: `pipeline/field_names.py` (field names from Core.dll data flow, unreliable; getters are folded/inlined).
- Tools: Il2CppInspectorRedux needs `DOTNET_ROOT=tools/dotnet10`; protodec emits one file (circular imports; `Any` import
  patched by build_protos.py); `tools/pylib` goes first on `sys.path`; UnityPy `FALLBACK_UNITY_VERSION = "6000.3.16f1"`.
  Beta clear protos: `work/beta` (LuaxY/dofus-unity-protocol-builder, Oct 2024).

## Updates & versions
- **Pack**: `dist/pack.json` fetched from `raw.githubusercontent.com/JustNao/karrelage-unity/main/dist` (env
  `KARRELAGE_PACK_URL`); if newer, download → verify sha256 → unpack to `%APPDATA%/fr.dofus.karrelage/datapack` (newest pack
  wins, `pick_pack`) → restart. `update_names.py` re-packages and commits dist/ (not pushed: push to publish).
- **App**: latest GitHub release (env `KARRELAGE_RELEASE_URL`) vs `CARGO_PKG_VERSION`; its `*-setup.exe` is checked against
  size + `digest` (no digest = refused) and run with `/P /UPDATE /R`.
- **Release format** (patch unless told otherwise): bump `X.Y.Z` in workspace `Cargo.toml`, `app/src-tauri/tauri.conf.json`,
  `app/package.json` and both entries of `app/package-lock.json` (`Cargo.lock` follows on the next cargo run); run the CI
  checks (Hard rules); one commit `Release X.Y.Z` with only those 5 files; lightweight tag `vX.Y.Z` on it; push main, then
  the tag. The tag triggers `.github/workflows/release.yml` (builds and publishes the NSIS installer as the GitHub release).
- Game version from the launcher's `%APPDATA%/zaap/repositories/production/dofus/dofus3/release.json`
  (`6.0_3.7.12.12` → `3.7.12.12`), stamped in `work/dump_input/version.txt`, `manifest.game`, `pack.json`.
- Proto tab (`names.rs`): checks bindings / required names / game fingerprint, runs `update_names.py`
  (`--repack`, `--from-game`) from a dev checkout.

## Game data facts
- AH row ints are unordered (uid / gid / type): `Data::resolve_gid_type`.
- Effect ids on the wire = `effects` table ids (= `possibleEffects[].actionId`), not `baseEffectId`.
- Default range = `diceNum..diceSide` (`diceSide == 0` → fixed).
- Item effects are listed in the game's order everywhere (`lib/effects.ts` `effectOrder`, `defaults_for`, stuff `effects_json`,
  brisage): weapon effects first, then `priority` (= `effectPriority`; the game's tooltips and forgemagie window), else group / order.
- Effects carry `group` (stats/main/secondary/damage/resist/weapon/other), `order` (in-game panel rank), `density`
  (effectPowerRate: AP 100, MP 90, vitality 0.2) and `stat` (+X and -X share it), computed in `export_pack.py`.
- Item **density** = Σ value × effect density (negatives at half their twin's rate; prospection excluded).
- Filterable effects: found on equipment (category 0) of levels 150–200; `weapon` group never offered.
- Item type categories: 0 equipment, 1 consumable, 2 resource. Companions = types 18, 121, 331–333 (`COMPANION_TYPES`).
- Svelte 5: plain `Map`/`Set` in `$state` aren't reactive (use `SvelteMap`/`SvelteSet`); `x ??= []` returns the raw value.

## Features (non-obvious facts only)
**HDV / auction** (`auction.rs`, `modules/auction`)
- Lot colours: blue = added effect, green = above default max, red = default effect missing; gold = good deal, green
  line = the player's own lot (role `ah_mine`: ExchangeBidSellerStartedEvent list + ExchangeBidHouseItemAddedEvent). The
  object uid is NOT the AH listing uid (checked): matched by sell id (assumed = listing uid), else gid + price + stats. Perfect = default
  damage / % resistances at max, main stats within 3 (vitality 10). Line styles in `lib/effects.ts`.
- Price vs density chart with least-squares line; good deal = ≥ `settings.hdv.goodZ` σ (default 2) above trend, needs ≥ 5
  lots (`lib/density.ts`). Companions plot price vs total xp of the level (`lib/companion.ts`; effects 2821 level, 2862 legendary).
- Pin (`lib/compare.ts` `pairRows`): other lots shown against the pinned one per stat.
- « Modifications » (`lib/lotDiff.ts`, on by default): the open item vs the last listing with other lots (`auction.previous`, session
  only; a scan finding the same lots keeps it). Lots matched by exact characteristics (action + value + text), not uid: same price = unchanged, else paired as a
  price change (any match), leftovers added / removed.
- Tabs Achat / Vente / Transcendance. Vente (`SellView.svelte`, `lib/sell.ts`): the player's copies of the open item
  (inventory + own lots on sale), price = 1,000 K under the cheapest filtered lot at least as dense, among lots with the
  same EXO (else same over) at least as high when any; none denser = the most expensive compared. Copies can be pinned.
- Transcendance (`lib/transcend.ts`): lock 2825 + `added` effect = runed lot; rune = type 211 with that effect/value;
  profit = cheapest transcended × (1 − tax) − lot − rune.
- On sale per category (role `ah_type`, removed by `ah_gone`) and listing changes (`ah_buy` removes a lot by uid, `ah_row`
  replaces a row, `ah_row_removed` removes one): purchase uids checked on a resource capture (row uid = listing uid), `ah_type` /
  `ah_gone` / `ah_row_removed` and equipment purchases not seen yet.

**Stored prices** (`prices.rs`)
- Per-unit price = median over stack sizes of each size's cheapest price / qty (lower middle on even counts); equipment =
  cheapest lot. Every listing / weekly-average batch is appended to `<app data>/prices/history.jsonl` (call `history`).
- `ObjectAveragePricesEvent` (role `avg_prices`) gives the 7-day average (entry: gid + two int64, the price is the larger:
  the other was never set on a 9679-entry capture). Priority: override > AH unit > avg.
- Purchases / row changes (`change_listing`): a row found by uid in any listing of the session, else by its gid: a resource's
  single row replaced / removed, a resource row with no listing yet starts one (equipment rows never do). Verified on
  work/capture_hdv_buy.jsonl (10 resource purchases): each BuyRequest is answered by InListUpdatedEvent (the row, same uid as
  the listing's) then BuyResultEvent (`object_uid` = that uid); leaving the window sends an empty listing (ignored: no price).

**Packets** (`packets.rs`): keeps the last 20 raw packets per type, decoded only when the tab lists/streams them.

**Recorder** (`recorder.rs`, `lib/stores/recorder.svelte.ts`, Paramètres « Développeur »): stores every packet of a category for
data analysis, `<app data>/recorder/<category>/<start, unix ms>.jsonl`. Off by default; records only while `settings.record.<category>`
and developer mode are both on. New category = an entry in `CATEGORIES`, a default in `settings.record`, a row in `RECORD_CATEGORIES`.
- Lines = `pipeline/sniff.py` records (`t srv dir len kind uid type name conf decoded hex`, whole payload in `hex`), after a first
  `{"header": ...}` (game version, `desc` = `builds.py` fingerprint, pack); `{"dropped": n}` marks a gap. Capture thread: names and a bytes copy
  into a bounded queue (full = dropped and counted); the writer thread decodes and writes, and only lives while a category is on.
- Fight = one file from `FightStartingEvent` (or a fight message when switched on during one) to `FightEndEvent` / `ContextDestroyEvent` /
  `MapInformationRequest` (end lost: 3 of the captures' 12 fights; never during the 9 others), with everything between except chat, party
  and keep-alive: names alone give 53 % of capture_poison. Files are per `srv`: two game clients on one server share a file (no client id in `RawMessage`).
- Forgemagie = a workshop session: the craft window's opening and the item put in are unnamed in 3.7, so a file opens at every
  `InteractiveUseRequest` and holds everything until `ExchangeLeaveEvent` / `DialogLeaveEvent` / `MapInformationRequest`; one
  without an `ExchangeCraftResultEvent` (category `keep`) is deleted when it closes (harvests, zaaps…). Crafts are recorded too.
- HDV = an auction house visit: from `ExchangeBidBuyerStartedEvent` / `ExchangeBidSellerStartedEvent` (or a listing / purchase
  message when switched on there) to `ExchangeLeaveEvent` / `DialogLeaveEvent` / `MapInformationRequest`, everything between: made to see
  what a purchase sends back (prices `change_listing`).
- Measured on the captures: about 1.1 KB per message, 0.4–0.85 MB per fight, 3.4 MB for a 3 min one with 4,300 messages (gzip: 22 × smaller).

**Brisage** (`brisage.rs`, `lib/brisage.ts`)
- Formula (kamamaster.fr, verified on a real break): runes = round2(3 × unit × jet × level / 200 + 1) × coef / 100 / rune
  weight; focus = own runes + half the weight of every other effect. Exo runes can't be focused. Expected values kept.
- Coefficients in `<app data>/brisage/coefs.json` (typed, or from `DecraftResultEvent` role `decraft`: per stack, coef 0–1
  float pair told apart by value (min / max), stored = min; rune gid = the Rune int that is a rune (type 78); uid resolved
  through `inventory::UidMap`, else guessed from runes). Every break appended to
  `breaks.json` (data to later model coefficient evolution).
- `drop` = `dropMonsterIds` non-empty (Temporis ignored). Breakable types in `BREAKABLE_TYPES`.
- « Focus » filter (`ui.focus`, an effect id): only items with that default effect; sources, break-even, profit and the
  detail summary use that focus's value (`valueOf`) instead of the best result.

**Crafting > Montures** (`lib/mounts.ts`): extraction gives N resources, N = generation (highest base-colour generation,
+1 for two colours; gen 1 left out). Effect 3836 = senile → 1 resource.

**Crafting > Familiers** (`lib/familiar.ts`, `familiar_xp.json`): xp per unit by gid from a community sheet (via huzounet.fr, minus the « Essence de » dungeon keeper essences, gone from the game;
2026-09-19; not in the game files: server-side, grows with level and rarity), n units give floor(n × xp); levels = the game's
evolutiveitemtypes table. A food costs the cheaper of buying and crafting it (`craftCost`). Same planner in the HDV companion card.

**Stuff** (`stuff.rs`, `modules/stuff`, `lib/stuff.ts`)
- Dofusbook import `https://www.dofusbook.net/api/stuffs/dofus/public/<id>` (link forms + `d-bk.net` 301). Cloudflare
  403s ureq → falls back to system curl with a browser UA. Only slot → gid / picture / scroll / exo are kept; stats and
  set bonuses come from the pack (`itemsets.json`).
- Totals (`compute`, verified vs Dofusbook): HP = 50 + 5 × level + vitality; initiative = Σ elements; dodge/withdrawal =
  wisdom / 10; tackle/escape = agility / 10; pods = 1000 + 5 × force; prospection = 100 + chance / 10.
- Icons from Dofusbook (Ankama's CDN lacks recent items), cached under `<app data>/stuff/icons`, served as data URLs (CSP).
- Prices are real only (override / AH price, never weekly avg) except craft ingredients (avg allowed). Owned items count
  at their perfect roll or the chosen inventory copy (`own_uid`) and are left out of prices.
- Solver (`solve`, web worker `lib/stuffWorker.ts`): branch and bound over scanned lots with set bonuses, node-limited.
  Build fm is searched as exo on lots (`EXO_BASE + stat` pseudo-stats) and not double-counted in `compute`. No combination carrying it
  (`solveWithFm`) = searched again with the fm counted as forged (like the sheet), flagged in the result.
- Dofusbook export (`lib/dofusbookExport.ts`, format documented there): worn positions 0–15 (0 amulette, 1 arme, 2/4
  anneaux, 3 ceinture, 5 bottes, 6 coiffe, 7 cape, 8 familier, 9–14 Dofus, 15 bouclier; 16 mount, 63 bag); exos sent as fm.
- Floating scan list (`ScanList.svelte`, localStorage `karrelage.scanlist`) of unscanned items.
- « Builds des joueurs »: another player's card (Card package, role `card`): CardViewResponse → Success → EquipmentCard
  {map worn position → preset.Equipment {gid, uid?, effects}} (or Unauthorized = private). Responses carry no character id:
  the CardViewRequest (named by anchor; view 1 = equipment) with the same envelope uid gives it (verified 3.7.12.12), name /
  breed / level from CardInfoResponse (level counts Omega levels, 360 seen: capped at 200 everywhere, Omega levels are cosmetic). The character's two
  int64 (id + another) can't be told apart: the player is stored under both; its three plain int32 = breed / level
  (largest other) / unknown (1, 3, 5 seen: looks like a breed too). Breed = the int whose breed's base skin (pack
  `breeds.json`, from the game's breeds table) heads a skins list of the card's look (a costume hides it: 1 card in 5),
  voted per field in `<app data>/stuff/breed.json`, else the voted field (`Stuff::breed_and_level`; right on
  work/capture_card3.jsonl, field order reversed too). Build id `player-<id>`, replaced on each inspection (user fields kept); `rolls` = exact rolls,
  counted when no lot is chosen. Event `stuff:player`. Base points / scrolls (EquipmentCard CharacteristicsInfo) not read.
  "Exporter vers Dofusbook" on a player build = `playerBuildLink` (`lib/dofusbookExport.ts`, 0 points / 100 scrolls).

**Inventory** (`inventory.rs`): ObjectItem gid / uid / quantity are unordered ints: the layout is learnt from the login
inventory (gid = most often a pack item, uid = most distinct; `learned` object_gid / object_uid), else guessed per object
(verified on 1487 captured objects). The content's two ObjectItemInventory lists and the entry's two ObjectItem fields are
both read (only one ever set on captures). Equipment from `InventoryContentEvent` (login only), updated by Object* events and
`ObjectMovementEvent` (named by anchor; uid / position told apart by value). Role `inventory`. Characteristics from
`CharacterCharacteristicsEvent`: unnamed ints told apart by value (base = invocations 1, prospection ≥ 100, six stats
costing ≤ 995 points; scroll ≤ 100), learned in `learned`. Level isn't read.

**Combat** (`combat.rs`, `lib/stores/combat.svelte.ts`, `modules/combat`)
- Fighters from ActorPositionInformation (role `fight`); MonsterFighter's gid / grade / level ints are unordered and learnt by
  voting (`<app data>/combat/layout.json`) — levels are often scaled, so no "largest int" guess.
- Fight start: FightJoin(Running)Event; end: FightEndEvent; deaths: GameActionFightEvent `death` (role `fight.death`),
  absence from FightSynchronizeEvent, or a spawn information without `alive` (role `fight.alive`; live fighters carry true). Summoned copies of starting monsters (doubles) are ignored, and so are the
  players' summons (summoner not a monster of the fight; summon details kept when a later message lacks them).
- Monsters' summons during the fight come as GameActionFightEvent summons by context (script-named SummonContextInformation:
  spawn information Monster = gid + grade or level, two unordered ints, both can be gids: the gid field is learnt (`layout.json`
  `summon_votes`, per `Message.field`) from summons with a single monster int, else the one whose other int is one of its
  grades, else a level of the fight's monsters (Songes: one room level for all), else the larger (Champ Champ 59 at level 226
  was read as Moon 226); actors = its
