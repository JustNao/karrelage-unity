# Loutil – passive Dofus 3 packet reader

Loutil reads the messages the Dofus 3 client exchanges with Ankama's servers and turns them into something useful.
Today: **auction-house (HDV) listings** with their effects and prices, deal detection, a *Transcendance* (rune) profit finder,
and a table of stored prices.

It is **strictly passive**: nothing is injected into, hooked on or automated in the game. The game folder is never modified
and Loutil only *listens* to the network traffic of the Dofus process (through Npcap). Nothing is sent anywhere: all data
stays on your computer.

---

# For users

## What to install
1. **Loutil** – run the installer (`Loutil_x.y.z_x64-setup.exe`, built with `npm run tauri build`, see below).
2. **[Npcap](https://npcap.com)** – the packet-capture driver Loutil uses to listen to the game's traffic. Install it with the
   default options. Loutil starts without it, but the capture stays unavailable (a banner tells you).
   Npcap's licence forbids redistributing it, which is why Loutil does not bundle it.
3. **Dofus 3** – nothing to configure; Loutil finds the game by itself.

Windows only (10/11, 64-bit).

## Using it
1. Start Loutil and flip the **capture switch** in the header to ON. It shows *Waiting for Dofus.exe…* until the game runs,
   then *Connecté à Dofus*. You can leave Loutil open at all times.
2. In the game, open items in the **auction house**. Each listing you open appears in the **Objets** tab (latest listing per item).

| Tab | What it does |
| --- | --- |
| **Objets** | Scanned items grouped by type (collapsible, searchable). Per item: price/density graph, *Bonnes affaires* (lots far above the price trend, also flagged by a green dot in the list), lots with their effects, filters on the right (Jet min / Jet parfait, per effect or per section), *Épingler* to compare any lot with a pinned one. |
| **Objets › Transcendance** | For equipment: lots carrying the transcendance lock and an extra effect (EXO) show what a *rune de transcendance* is worth. Lists unlocked lots (no overmax effect) where buying the lot + the rune and reselling is profitable, with investment, profit, a focus per rune, and *Enregistrer* to keep candidates for later. |
| **Prix enregistrés** | Per-unit price of every item you opened, by category › type › item, with a manual price override. Prices come from (highest priority first): your manual price, the price read when you opened the item, the 7-day average sent by the game. |
| **Paquets** *(developer mode)* | Raw packet inspector, recording only while the tab is open. |

Familiers and montiliers are tracked by level (price against the xp curve) and *statut légendaire* instead of stats.

## Good to know
- Rune prices are only as fresh as the last time you opened the rune in the auction house; Loutil warns when they are older than a day
  or when only the weekly average is known.
- Data is stored under `%APPDATA%\fr.dofus.loutil.packets\` (scanned items, prices, name overrides). Delete the folder to reset.
- After a **Dofus update** the game data may need to be regenerated by the maintainer (see below); a newer data pack can be dropped in
  `%APPDATA%\fr.dofus.loutil.packets\datapack\` and wins over the bundled one.
- The data pack contains text extracted from Ankama's files: do not republish it publicly.

# For developers

Two halves: the **Tauri app** (what users run) and a **Python pipeline** (author only) that turns the game files into a small
*data pack* (`datapack/`) the app loads. More conventions and protocol notes live in [CLAUDE.md](CLAUDE.md).

## Repository layout
```
crates/core      wire.rs (varint, framing, envelope), stream.rs (TCP reorder), pcap.rs (wpcap.dll loaded at runtime), capture.rs (Dofus.exe sockets + sniff threads)
crates/proto     dynamic protobuf decoding from datapack/protocol.desc, clear message/field names
crates/data      data pack loader: items, effects, item types, strings, bindings
crates/modules   Module trait + Hub; one file per feature: packets.rs, auction.rs, prices.rs
app/             Tauri shell (src-tauri) + Svelte 5 / Vite UI (src/modules/<id>/ are auto-registered tabs)
pipeline/        game files -> data pack (python)
fixtures/        synthetic AH packet + expected output (golden test)
datapack/        generated (gitignored)      work/   generated, except work/overrides.json (hand-confirmed names – keep!)
tools/           downloaded third-party tools (gitignored)
```

## Prerequisites
| For | Needs |
| --- | --- |
| App | Rust (stable, MSVC toolchain), Node 20+, [Tauri 2 prerequisites](https://tauri.app/start/prerequisites/) (WebView2, MSVC build tools) |
| Running capture | [Npcap](https://npcap.com) |
| Pipeline | Python 3.12+, the tools below |

### Tools (in `tools/`, not committed)
- **Il2CppInspectorRedux** (`tools/inspector`) – dumps `GameAssembly.dll` + `global-metadata.dat` (metadata v39) to DummyDlls. Needs **.NET 10**,
  installed locally in `tools/dotnet10` (`tools/dotnet-install.ps1`); set `DOTNET_ROOT`. (Il2CppDumper in `tools/il2cppdumper` cannot read v39.)
- **protodec** (`tools/protodec`) – DummyDll → obfuscated `.proto` (single file: circular imports).
- **Python libs** in `tools/pylib` (installed with `pip install --target tools/pylib grpcio-tools protobuf UnityPy`; put first on `sys.path`;
  the protobuf runtime must match the generated code).
- Beta protos with clear names: [LuaxY/dofus-unity-protocol-builder](https://github.com/LuaxY/dofus-unity-protocol-builder) cloned in `work/beta`.

## Build pipeline (run again after every game update)
From the repo root in Git Bash (Windows: `export PYTHONUTF8=1`).

```bash
# 1. copy (never modify) the game files and dump them
export DOTNET_ROOT=$PWD/tools/dotnet10 DOTNET_MULTILEVEL_LOOKUP=0
cp <game>/GameAssembly.dll <game>/Dofus_Data/il2cpp_data/Metadata/global-metadata.dat work/dump_input/
tools/inspector/Il2CppInspectorRedux.CLI-win-x64/Il2CppInspector.Redux.CLI.exe process \
  work/dump_input/GameAssembly.dll work/dump_input/global-metadata.dat -o work/dump -d --unity-version 6000.0.0
# 2. DummyDlls -> obfuscated protos
tools/protodec/protodec.exe work/dump/dll/Ankama.Dofus.Protocol.Game.dll work/proto/game.proto
tools/protodec/protodec.exe work/dump/dll/Ankama.Dofus.Protocol.Connection.dll work/proto/connection.proto
python pipeline/build_protos.py             # compile protos, writes work/pb/protocol.desc
# 3. clear names (obfuscated names rotate on every update)
python pipeline/match_protos.py             # ~1 min: structural match with the beta protos -> work/mapping.json
python pipeline/import_reference_names.py <list.txt>   # optional: community obf->clear list -> pipeline/reference/message_names.json
#    pin confirmed names in work/overrides.json (they win over everything), roles/fields in pipeline/bindings.json
# 4. game data: items, effects, item types, i18n
python pipeline/extract_gamedata.py --refresh   # copies Content/Data + Content/I18n into work/gamedata, parses with UnityPy
# 5. assemble the data pack the app loads
python pipeline/export_pack.py              # -> datapack/
python pipeline/make_fixtures.py            # only if the demo packet / formatter changed
```
All of the above except step 1's copy can be run from the app: developer mode › **Noms** tab checks that the pack matches the installed game and has
a *Calculer les noms* button (`pipeline/update_names.py`) and a *Tout régénérer depuis le jeu* button (`--from-game`: the whole chain). Restart afterwards.
Name precedence: auto beta match < `pipeline/reference/message_names.json` < `work/overrides.json`.
`pipeline/bindings.json` maps *roles* (AH list fields, effect fields, average prices…) to the build-specific obfuscated field names:
it usually needs updating after a game update, app code never hard-codes obfuscated names.

CLI alternative to the app for recording fixtures: `python pipeline/sniff.py` (add `--raw` for payload hex) writes JSONL.

## Run, test, build the app
```bash
cargo test                      # unit tests + golden test (Rust output == python formatter output; skipped without datapack/)
cd app && npm install
npm run tauri dev               # dev app (capture starts OFF; tick "Développeur" for the Paquets tab and "Injecter la démo")
npm run check                   # svelte-check
npm run tauri build             # NSIS installer in target/release/bundle/nsis/, bundles datapack/ as a resource
```
The installer needs `datapack/` generated first (step 5 above).

## Adding a feature
1. Rust: new file in `crates/modules/src/` implementing `Module` (`interest`, `on_message`, `call`, optional `format`/`init`/`wants`),
   registered in `all()` in `lib.rs`.
2. UI: new folder `app/src/modules/<id>/` with `index.ts` (`{id, title, order, devOnly?, component}`) and `View.svelte`; it becomes a tab
   automatically. Talk to the backend with `call(module, method, args)` and `on("<module>:<event>", fn)`. Tabs with side-by-side panels
   use `Columns` (`lib/columns.svelte.ts`) for resizable columns.
3. New messages: confirm their names in `work/overrides.json`, add field roles to `pipeline/bindings.json`, re-run `export_pack.py`.

## Principles
- **Passive only.** Never modify the game folder or process; copies only; capture = Npcap sniffing.
- Obfuscated names are build-specific: use clear names or `bindings.json` roles.
- One commit per working feature.
